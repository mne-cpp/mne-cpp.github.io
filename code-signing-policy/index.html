Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

This policy covers the Windows binaries that MNE-CPP publishes on its download page and on GitHub Releases. It is maintained in the repository next to the pipeline it describes; changes to it are reviewed like code.

Current status. The release pipeline is ready to sign, but no MNE-CPP release carries a SignPath Foundation signature yet: the project's release signing policy in SignPath is not active yet. The next release is published once its Windows binaries can be signed, and this page will name it. Until then, check every download against its SHA-256 checksum.

What is signed​

Only binaries that the MNE-CPP team builds from its own source code are signed with the SignPath Foundation certificate:

Release assetSigned filesSignPath artifact configuration
mne-cpp-<version>-windows-dynamic-x86_64.zipMNE-CPP's applications, tools and libraries (mne_*.exe, mne_*.dll) and plugins (mne_*_plugins/*.dll) inside the archivewindows-archive
mne-cpp-<version>-windows-static-x86_64.zipThe same, statically linkedwindows-archive
mne-cpp-<version>-windows-installer-x86_64.exeThe installer executable; its payload is the signed archive contentwindows-installer

Not signed with the MNE-CPP certificate:

  • Third-party components shipped alongside MNE-CPP — Qt, ONNX Runtime and the compiler runtime — keep their publishers' signatures, or none. MNE-CPP never signs them.
  • Examples and test programs (ex_*, test_*) that some archives contain.
  • macOS and Linux packages. Their signing (Apple Developer ID on macOS) is separate from SignPath and recorded in each release's notes.

Provenance​

Every signed file is built by the GitHub Actions workflows release-windows.yml and release-installer.yml from a release tag of mne-tools/mne-cpp. The workflow uploads the unsigned file as a build artifact, and SignPath fetches it from that workflow run, so the signature ties the binary to the public source and build scripts of the tagged commit.

Before a request is submitted, the pipeline checks that every file the artifact configuration selects carries a Windows version resource with ProductName MNE-CPP and the release version as ProductVersion (scripts/release/pe_metadata.py); SignPath enforces the same restrictions on its side and refuses to sign any file that does not match. The resource is generated for every MNE-CPP executable and library from cmake/mne_version_info.rc.in and the version in src/CMakeLists.txt.

What a signature tells you​

A valid signature by SignPath Foundation means that the file was produced by MNE-CPP's release pipeline from the public source code and has not been modified since. It does not mean that the software was audited, and it makes no statement about fitness for a particular purpose; MNE-CPP is provided under the BSD 3-Clause License.

Owners of the mne-tools GitHub organization, among them Eric Larson, hold administrative access to the repository through the organization; they do not take part in MNE-CPP's development or release signing.

All team members must use multi-factor authentication for GitHub and for SignPath. Pull requests that change build scripts or CI workflows get particular attention in review, because those files determine what ends up in a signed binary.

How a release is signed​

  1. A maintainer tags a release on main; GitHub Actions builds the Windows archives and the installer from that tag.
  2. The pipeline checks the product metadata of every file to be signed and fails on any mismatch.
  3. It submits the signing request to SignPath with the release version as parameter.
  4. The signing approver reviews the request — the tagged commit and the workflow run it came from — and approves or rejects it. No release is signed without this manual approval.
  5. The signed files are verified with signtool verify and published with SHA-256 checksums.

Privacy statement​

MNE-CPP applications​

This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.

MNE-CPP contains no telemetry, usage analytics, crash reporting or automatic update checks. The network functions below run only when you, or whoever installs or operates the software, configure and start them:

  • Real-time acquisition in MNE Scan connects to the devices and data sources you configure: networked amplifiers and MEG systems (BabyMEG, Natus), an MNE real-time server (mne_rt_server) or FIFF simulator, a FieldTrip buffer, or Lab Streaming Layer streams, whose discovery uses your local network. mne_rt_server listens on TCP ports while it runs.
  • MNE Analyze Studio's assistant is off until you enter an API key or endpoint. It then sends your prompts and the analysis context it needs to the provider you selected — for example OpenAI, Google, GitHub Models or Anthropic — under that provider's privacy policy.
  • Python-based features that need Python packages create a Python environment and install the packages from the Python Package Index when you start them.
  • The installer downloads data only for optional components that are off by default: the MNE sample dataset from OSF and MNE-Python from the Python Package Index.
  • Links in the applications, such as to this website, open your web browser.

The browser versions of MNE Analyze, MNE Anonymize, MNE Browse and MNE Inspect process the files you open locally in the browser; they do not upload them.

This website​

This website is hosted on GitHub Pages; GitHub processes the requests to it as described in the GitHub Privacy Statement. The site sets no cookies and uses no analytics. Search runs in your browser. The download page asks the GitHub API for the current release assets, and the home page loads contributor avatars from GitHub. Your light or dark theme choice is kept in your browser's local storage.

Verifying a signed download​

Once a release is signed, Windows shows SignPath Foundation as the publisher. To check a file yourself, open its Properties → Digital Signatures tab, or run in PowerShell:

Get-AuthenticodeSignature .\mne_scan.exe | Format-List Status, SignerCertificate

Status must be Valid and the signer certificate must be issued to SignPath Foundation. With the Windows SDK, signtool verify /pa /v .\mne_scan.exe prints the full certificate chain and timestamp. In the archives, each MNE-CPP .exe and .dll carries its own signature; check the ones you run. Independently of signatures, compare every download with its SHA-256 checksum as described on the download page.

Reporting a problem​

If you believe a file signed for MNE-CPP violates this policy, please report it through GitHub Security Advisories as described in our security policy, and to SignPath at support@signpath.io.
